# Renga MCP Server

MCP-сервер для Renga, который позволяет ИИ-агенту проектировать в Renga через официальный COM API: создавать уровни, координационные оси, стены, колонны, балки и перекрытия, сохранять проект и экспортировать IFC.

Сервер работает локально, общается с MCP-клиентом по stdio и не требует ручного клика по интерфейсу Renga. Агент получает набор типизированных инструментов и может построить модель по текстовому заданию, координатам или заранее подготовленному плану.

## Что умеет сервер

- Создавать этажи и уровни с заданными отметками.
- Строить координационные оси, в том числе диагональные.
- Возводить стены по базовым линиям с заданной высотой.
- Расставлять колонны по координатам и высоте.
- Создавать балки между 3D-точками.
- Создавать перекрытия по прямоугольнику или произвольному полигону.
- Сохранять результат в нативный `.rnp`.
- Экспортировать модель в `.ifc` для проверки, обмена и дальнейшей обработки.
- Работать с уже открытым проектом Renga или запускать Renga автоматически.
- Возвращать структурированный JSON: ID объектов, типы, уровни, оси, параметры и ошибки.

## Кому подойдёт

- BIM-специалистам, которым нужно быстро собрать каркас здания или типовой этаж по координатам.
- Инженерам и проектировщикам, которые хотят автоматизировать рутинное создание элементов в Renga.
- Преподавателям и студентам: воспроизводимые лабораторные, демонстрации и учебные проекты.
- Разработчикам, которые делают ИИ-агентов для CAD/BIM и хотят готовый MCP-интерфейс к Renga.
- Командам, которым нужен программный мост между Renga и внешними расчётами, каталогами или генераторами планировок.

## Почему это удобно

- **Нативные объекты Renga.** Стены, колонны, балки и перекрытия создаются через `IModel.CreateObject`, а не рисуются линиями или имитацией.
- **Официальный COM API.** Никакой автоматизации мыши и клавиатуры, никаких скриншотов и хрупких сценариев интерфейса.
- **Понятные единицы.** Пользователь задаёт метры, сервер сам переводит их во внутренние миллиметры Renga.
- **Готовый MCP-протокол.** Инструменты сразу видны OpenCode, Claude Desktop и другим MCP-клиентам.
- **Расширяемая архитектура.** Новые команды добавляются в C# без переписывания транспорта и подключения к Renga.
- **Проверяемый результат.** После работы остаётся обычный `.rnp`, который можно открыть в Renga, и `.ifc` для независимой проверки.
- **Аккуратный stdio.** Весь лог идёт в `stderr`, поэтому MCP-канал не засоряется.

## Быстрый старт

### 1. Требования

- Windows 10/11 x64.
- Renga Professional или Renga Standard (проверено на Renga Professional 9.2).
- .NET 8 SDK для сборки или .NET 8 Desktop Runtime для готового `.exe`.
- Зарегистрированный COM-сервер `Renga.Application.1` (обычно регистрируется при установке Renga).

### 2. Сборка

В примерах ниже используется нейтральный путь установки `C:\Tools\RengaMcpServer`. Замените его на свой каталог.

```powershell
cd "C:\Tools\RengaMcpServer"

& "C:\Program Files\dotnet\dotnet.exe" build -c Release
```

Готовый файл:

```text
C:\Tools\RengaMcpServer\bin\Release\net8.0-windows\RengaMcpServer.exe
```

Проверка:

```powershell
& ".\bin\Release\net8.0-windows\RengaMcpServer.exe" --version
```

Ожидаемый вывод:

```text
RengaMcpServer 1.0.0
```

### 3. Подключение к MCP-клиенту

Добавьте сервер в конфигурацию OpenCode или Claude Desktop (примеры ниже) и перезапустите клиент. При первом вызове сервер подключится к запущенной Renga или запустит её.

## Конфигурация OpenCode

Файл `opencode.json` в корне проекта или `~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "renga": {
      "type": "local",
      "command": [
        "C:\\Tools\\RengaMcpServer\\bin\\Release\\net8.0-windows\\RengaMcpServer.exe"
      ],
      "enabled": true,
      "environment": {
        "RENGA_MCP_VISIBLE": "1"
      }
    }
  }
}
```

После изменения конфигурации перезапустите OpenCode.

## Конфигурация Claude Desktop

Файл `%APPDATA%\Claude\claude_desktop_config.json`:

```json
{

    "renga": {
      "command": "C:\\Tools\\RengaMcpServer\\bin\\Release\\net8.0-windows\\RengaMcpServer.exe",
      "args": [],
      "env": {
        "RENGA_MCP_VISIBLE": "1"
      }
    }
  }

```

После изменения конфигурации полностью перезапустите Claude Desktop.

| Переменная | Значения | По умолчанию | Назначение |
|---|---|---|---|
| `RENGA_MCP_VISIBLE` | `1` / `0` | `1` | Показывать или скрывать окно Renga |

## Как это работает

```text
MCP-клиент (OpenCode / Claude)
        │  JSON-RPC 2.0 через stdio
        ▼
RengaMcpServer (C# / .NET 8, STA)
        │  COM API
        ▼
Renga Professional / Standard
```

- Сервер работает в STA-потоке, как требует COM API Renga.
- Подключение идёт через ROT к уже запущенному экземпляру, иначе Renga запускается по ProgID `Renga.Application.1`.
- Все изменения модели выполняются в операциях Renga.
- Ответы инструментов возвращаются как JSON-текст в MCP-контенте; ошибки помечаются `isError: true`.
- Сервер не завершает Renga после выхода — приложение остаётся открытым.

## Инструменты

Все пользовательские координаты, отметки, высоты и толщины — в метрах. `levelId` — локальный числовой ID уровня, который возвращают `renga_list_levels` и `renga_ping`.

### `renga_ping`

Проверка связи с Renga. Возвращает версию и название продукта, наличие проекта, путь к проекту, количество объектов, уровни, оси и признак наличия геометрии.

Параметры: нет.

### `renga_new_project`

Создаёт новый чистый проект. Если проект уже открыт, он закрывается с потерей несохранённых изменений.

Параметры: нет.

### `renga_open_project`

Открывает существующий `.rnp`. Текущий проект закрывается с потерей несохранённых изменений.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `path` | string | да | Путь к `.rnp` |

### `renga_list_levels`

Возвращает уровни проекта: `id`, `uniqueId`, `name`, `elevation` (м), `elevationMm`, `originZ` (м).

Параметры: нет.

### `renga_create_level`

Создаёт уровень с заданной отметкой.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | string | да | Имя уровня, например `Level 1` |
| `elevation` | number | да | Отметка уровня в метрах |

Особенность: уровни создаются через официальный импорт IFC-заготовки. Вызывайте этот инструмент до создания геометрии.

### `renga_create_axis`

Создаёт координационную ось (нативный `Axis`) между двумя точками в плане.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | string | да | Имя оси, например `A` или `1` |
| `x1` | number | да | X начала, м |
| `y1` | number | да | Y начала, м |
| `x2` | number | да | X конца, м |
| `y2` | number | да | Y конца, м |

Поддерживаются ортогональные и диагональные оси. Вызывайте до создания геометрии.

### `renga_create_wall`

Создаёт прямую стену по базовой линии на уровне.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `x1` | number | да | X начала базовой линии, м |
| `y1` | number | да | Y начала базовой линии, м |
| `x2` | number | да | X конца базовой линии, м |
| `y2` | number | да | Y конца базовой линии, м |
| `levelId` | integer | да | ID уровня-хоста |
| `height` | number | да | Высота стены, м |

Толщина берётся из стиля Renga по умолчанию (обычно 200 мм).

### `renga_create_column`

Создаёт колонну.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `x` | number | да | X, м |
| `y` | number | да | Y, м |
| `height` | number | да | Высота, м |
| `levelId` | integer | нет | ID уровня-хоста |
| `elevation` | number | нет | Абсолютная отметка основания, м |

Если `levelId` не задан, выбирается ближайший к `elevation` уровень (или самый нижний, если отметка не задана). Если `elevation` не задана, колонна начинается на отметке уровня.

### `renga_create_beam`

Создаёт балку между двумя абсолютными 3D-точками.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `x1` | number | да | X начала, м |
| `y1` | number | да | Y начала, м |
| `z1` | number | да | Z начала, м |
| `x2` | number | да | X конца, м |
| `y2` | number | да | Y конца, м |
| `z2` | number | да | Z конца, м |
| `levelId` | integer | нет | ID уровня-хоста |

Если `levelId` не задан, выбирается уровень, ближайший к `z1`.

### `renga_create_floor`

Создаёт перекрытие (нативный `Floor`) по замкнутому контуру или прямоугольнику.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `levelId` | integer | да | ID уровня-хоста |
| `thickness` | number | да | Толщина, м |
| `points` | array | нет | Массив точек `{ "x": ..., "y": ... }`, не менее 3 |
| `x1` | number | нет | X угла прямоугольника, м |
| `y1` | number | нет | Y угла прямоугольника, м |
| `x2` | number | нет | X противоположного угла, м |
| `y2` | number | нет | Y противоположного угла, м |

Нужно передать либо `points`, либо `x1/y1/x2/y2`. Возвращает площадь контура в м².

### `renga_save_project`

Сохраняет проект в `.rnp`.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `path` | string | да | Путь назначения |

Расширение `.rnp` добавляется автоматически. Существующий файл перезаписывается. Каталог создаётся при необходимости.

### `renga_export_ifc`

Экспортирует текущую модель в IFC.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `path` | string | да | Путь назначения |

Расширение `.ifc` добавляется автоматически. Каталог создаётся при необходимости.

## Рекомендуемый порядок работы

1. `renga_new_project`
2. `renga_create_level` для всех этажей, например 0, 3, 6 м
3. `renga_create_axis` для всех осей, например A, B, 1, 2
4. `renga_list_levels` — получить `levelId`
5. `renga_create_wall`, `renga_create_column`, `renga_create_beam`, `renga_create_floor`
6. `renga_save_project`
7. `renga_export_ifc`

Порядок «уровни и оси → геометрия» важен: после появления геометрии добавить уровень или ось через публичный COM API Renga нельзя.

## Особенность работы с уровнями и осями

Публичный COM API Renga 9.2 имеет ограничения:

- `ILevel.Elevation` доступно только для чтения.
- Параметр `LevelElevation` доступен только для чтения.
- `IModel.CreateObject` для `Level` игнорирует `Z` в `Placement3D`, и уровень создаётся с отметкой 0.
- `IModel.CreateObject` для `Axis` возвращает `null`.

Поэтому сервер использует официальный маршрут: генерирует временный IFC4-файл с уровнями и/или осями, импортирует его через `IApplication.ImportIfcProject`, проверяет результат и удаляет временные объекты-носители. В проекте остаются настоящие объекты Renga типов `Level` и `Axis`.

Что это значит на практике:

- `renga_create_level` и `renga_create_axis` пересобирают каркас уровней и осей.
- Их нужно вызывать до создания стен, колонн, балок и перекрытий.
- Если геометрия уже есть, инструменты возвращают понятную ошибку и не меняют проект.
- Временный IFC создаётся в `%TEMP%\RengaMcp` и удаляется после импорта.
- Импортированные уровни и оси сохраняются в `.rnp` и переживают закрытие и повторное открытие.

Если открыть готовый проект с осями после перезапуска MCP-сервера, сервер увидит оси, но не сможет прочитать их координаты через COM: у `Axis` нет публичного getter геометрии. В этом случае добавление новых уровней и осей блокируется, а создание геометрии продолжает работать.

## Проверка MCP вручную

Сервер читает по одной JSON-RPC строке из stdin и пишет по одной строке в stdout. Минимальная последовательность:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"manual-test","version":"1.0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"renga_ping","arguments":{}}}
```

Логи сервера должны идти в `stderr`, а не в `stdout`.

## Перегенерация COM interop

Interop-сборка уже включена в репозиторий: `libs/Interop.RengaCOMAPI.dll`. Она сгенерирована из типа библиотеки установленной Renga:

- TypeLib GUID: `{0EC5D324-8B9F-4D30-84ED-AB711618D1C1}`
- Файл типа библиотеки: `C:\Program Files\Renga Professional\RengaCOMAPI.dll`

Если вы обновили Renga или используете другую версию, interop нужно перегенерировать.

`TlbImp.exe` входит в Windows SDK, например:

```text
C:\Program Files (x86)\Microsoft SDKs\Windows\v10.0A\bin\NETFX 4.8 Tools\x64\TlbImp.exe
```

`TlbImp.exe` может не найти `TLBREF.DLL`. Надёжный способ — скопировать оба файла в один временный каталог и запускать оттуда:

```powershell
$work = "C:\Temp\renga-tlbimp"
New-Item -ItemType Directory -Force -Path $work | Out-Null

Copy-Item "C:\Program Files (x86)\Microsoft SDKs\Windows\v10.0A\bin\NETFX 4.8 Tools\x64\TlbImp.exe" "$work\TlbImp.exe" -Force
Copy-Item "C:\Windows\Microsoft.NET\Framework64\v4.0.30319\TLBREF.DLL" "$work\TLBREF.DLL" -Force

& "$work\TlbImp.exe" `
  "C:\Program Files\Renga Professional\RengaCOMAPI.dll" `
  /out:"C:\Tools\RengaMcpServer\libs\Interop.RengaCOMAPI.dll" `
  /namespace:Renga `
  /machine:X64
```

После замены DLL пересоберите проект:

```powershell
& "C:\Program Files\dotnet\dotnet.exe" build -c Release
```

Для 32-битной Renga генерируйте interop x86 и измените `PlatformTarget` в `.csproj` на `x86`.

## Ограничения и безопасность

- Сервер предназначен для локального использования и не имеет аутентификации.
- `renga_new_project` и `renga_open_project` закрывают текущий проект с потерей несохранённых изменений.
- `renga_save_project` перезаписывает существующий `.rnp`.
- Пересборка уровней и осей выполняется только при отсутствии геометрии.
- Координаты осей нельзя прочитать обратно через COM; после перезапуска сервера добавление осей и уровней в проект с осями блокируется.
- При нескольких запущенных экземплярах Renga ROT может вернуть не тот экземпляр. Для предсказуемой работы держите один экземпляр.
- Interop-сборка сгенерирована из установленной Renga. При публикации проекта проверьте условия лицензирования Renga и её SDK.
- Лицензия самого проекта пока не выбрана.

## Диагностика

### `dotnet` не найден

Используйте полный путь:

```powershell
& "C:\Program Files\dotnet\dotnet.exe" build -c Release
```

Либо добавьте `C:\Program Files\dotnet` в `PATH`.

### `Renga.Application.1 is not registered`

- Запустите Renga вручную и убедитесь, что она работает.
- Проверьте разрядность: interop и сервер должны быть x64 для 64-битной Renga.
- При необходимости переустановите или восстановите Renga.

### Первый вызов долго не отвечает

Если Renga не была запущена, сервер запускает её. Первый вызов может занять 10–30 секунд.

### `Cannot create a level after geometry exists`

Это ожидаемое ограничение. Создайте новый проект и сначала все уровни и оси, затем геометрию.

### `IFC seed verification failed`

Импорт IFC не создал ожидаемые уровни или оси. Проверьте версию Renga и лог в `stderr`. Для другой версии Renga может потребоваться перегенерация interop или обновление генератора IFC.

### `Renga already has an active operation`

Предыдущая операция не завершилась. Перезапустите Renga и повторите вызов.

### MCP-клиент не видит инструменты

- Проверьте абсолютный путь к `.exe` в конфигурации.
- Перезапустите клиент.
- Проверьте логи MCP-клиента: сервер пишет диагностику в `stderr`.
- Убедитесь, что `stdout` не засоряется посторонними сообщениями.

## Планы по упаковке

Чтобы установка была простой для специалистов, дальше можно сделать:

- GitHub Release с готовым self-contained `.exe` (без необходимости отдельно ставить .NET).
- Один вариант поставки: `.zip` с exe и примером конфигурации.
- Установщик или скрипт установки, который копирует файлы в `C:\Tools\RengaMcpServer` и добавляет пример конфигурации MCP.
- Публикацию в GitHub Releases с версиями и changelog.
- Опционально — пакет для winget после стабилизации интерфейса.

Это позволит поставлять сервер как обычный инструмент, без сборки из исходников.
