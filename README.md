# Renga MCP Server

MCP-сервер для Renga, который позволяет ИИ-агенту проектировать в Renga через официальный COM API: создавать уровни, координационные оси, стены, колонны, балки, перекрытия, двери, окна, крыши и листы чертежей, сохранять проект, экспортировать IFC и выпускать листы в PDF/DXF/DWG.

Сервер работает локально, общается с MCP-клиентом по stdio и не требует ручного клика по интерфейсу Renga. Агент получает набор типизированных инструментов и может построить модель по текстовому заданию, координатам или заранее подготовленному плану.

## Что умеет сервер

- Создавать этажи и уровни с заданными отметками.
- Строить координационные оси, в том числе диагональные.
- Возводить стены по базовым линиям с заданной высотой.
- Расставлять колонны по координатам и высоте.
- Создавать балки между 3D-точками.
- Создавать перекрытия по прямоугольнику или произвольному полигону.
- Вставлять двери и окна в существующие стены.
- Создавать проёмы в перекрытиях и крышах.
- Создавать плоские крыши по контуру с заданным смещением от уровня.
- Ставить пластины, ленточные и столбчатые фундаменты.
- Создавать помещения с автоматическим расчётом контура по стенам.
- Строить лестницы, ограждения и пандусы по базовой линии.
- Читать и менять любые доступные нативные параметры объектов: толщину, высоту, ширину, отступы, марки и другие.
- Работать с материалами: создавать простые материалы, назначать материалы колоннам и балкам, просматривать слоистые материалы.
- Просматривать стили и создавать стили дверей, окон, колонн, балок и плит.
- Создавать пользовательские свойства, назначать их типам объектов и заполнять значения.
- Сохранять результат в нативный `.rnp`.
- Экспортировать модель в `.ifc` для проверки, обмена и дальнейшей обработки.
- Создавать листы чертежей, переименовывать и удалять их.
- Читать штампы листов и их ячейки.
- Экспортировать листы в PDF, DXF, DWG и XPS.
- Работать с уже открытым проектом Renga или запускать Renga автоматически.
- Возвращать структурированный JSON: ID объектов, типы, уровни, оси, параметры и ошибки.

## Кому подойдёт

- BIM-специалистам, которым нужно быстро собрать каркас здания или типовой этаж по координатам.
- Инженерам и проектировщикам, которые хотят автоматизировать рутинное создание элементов в Renga.
- Преподавателям и студентам: воспроизводимые лабораторные, демонстрации и учебные проекты.
- Разработчикам, которые делают ИИ-агентов для CAD/BIM и хотят готовый MCP-интерфейс к Renga.
- Командам, которым нужен программный мост между Renga и внешними расчётами, каталогами или генераторами планировок.

## Почему это удобно

- **Нативные объекты Renga.** Стены, колонны, балки, перекрытия, двери, окна и крыши создаются через `IModel.CreateObject`, а не рисуются линиями или имитацией.
- **Официальный COM API.** Никакой автоматизации мыши и клавиатуры, никаких скриншотов и хрупких сценариев интерфейса.
- **Полный контроль над параметрами.** Агент может прочитать все параметры объекта и изменить толщину, высоту, материал, марку и другие доступные значения.
- **Пользовательские свойства.** Можно зарегистрировать собственные атрибуты, назначить их типам объектов и заполнять значения для конкретных элементов.
- **Понятные единицы.** Пользователь задаёт метры, сервер сам переводит их во внутренние миллиметры Renga.
- **Готовый MCP-протокол.** Инструменты сразу видны OpenCode, Claude Desktop и другим MCP-клиентам.
- **Расширяемая архитектура.** Новые команды добавляются в C# без переписывания транспорта и подключения к Renga.
- **Проверяемый результат.** После работы остаётся обычный `.rnp`, который можно открыть в Renga, и `.ifc` для независимой проверки.
- **Аккуратный stdio.** Весь лог идёт в `stderr`, поэтому MCP-канал не засоряется.

## Быстрый старт

### 1. Требования

- Windows 10/11 x64.
- Renga Professional или Renga Standard (проверено на Renga Professional 9.2).
- .NET 8 SDK для сборки или .NET 8 Desktop Runtime для готового `.exe`.
- Зарегистрированный COM-сервер `Renga.Application.1` (обычно регистрируется при установке Renga).

### 2. Сборка

В примерах ниже используется нейтральный путь установки `C:\Tools\RengaMcpServer`. Замените его на свой каталог.

```powershell
cd "C:\Tools\RengaMcpServer"

& "C:\Program Files\dotnet\dotnet.exe" build -c Release
```

Готовый файл:

```text
C:\Tools\RengaMcpServer\bin\Release\net8.0-windows\RengaMcpServer.exe
```

Проверка:

```powershell
& ".\bin\Release\net8.0-windows\RengaMcpServer.exe" --version
```

Ожидаемый вывод:

```text
RengaMcpServer 1.0.0
```

### 3. Подключение к MCP-клиенту

Добавьте сервер в конфигурацию OpenCode или Claude Desktop (примеры ниже) и перезапустите клиент. При первом вызове сервер подключится к запущенной Renga или запустит её.

## Конфигурация OpenCode

Файл `opencode.json` в корне проекта или `~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "renga": {
      "type": "local",
      "command": [
        "C:\\Tools\\RengaMcpServer\\bin\\Release\\net8.0-windows\\RengaMcpServer.exe"
      ],
      "enabled": true,
      "environment": {
        "RENGA_MCP_VISIBLE": "1"
      }
    }
  }
}
```

После изменения конфигурации перезапустите OpenCode.

## Конфигурация Claude Desktop

Файл `%APPDATA%\Claude\claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "renga": {
      "command": "C:\\Tools\\RengaMcpServer\\bin\\Release\\net8.0-windows\\RengaMcpServer.exe",
      "args": [],
      "env": {
        "RENGA_MCP_VISIBLE": "1"
      }
    }
  }
}
```

После изменения конфигурации полностью перезапустите Claude Desktop.

## Переменные окружения

| Переменная | Значения | По умолчанию | Назначение |
|---|---|---|---|
| `RENGA_MCP_VISIBLE` | `1` / `0` | `1` | Показывать или скрывать окно Renga |

## Как это работает

```text
MCP-клиент (OpenCode / Claude)
        │  JSON-RPC 2.0 через stdio
        ▼
RengaMcpServer (C# / .NET 8, STA)
        │  COM API
        ▼
Renga Professional / Standard
```

- Сервер работает в STA-потоке, как требует COM API Renga.
- Подключение идёт через ROT к уже запущенному экземпляру, иначе Renga запускается по ProgID `Renga.Application.1`.
- Все изменения модели выполняются в операциях Renga.
- Ответы инструментов возвращаются как JSON-текст в MCP-контенте; ошибки помечаются `isError: true`.
- Сервер не завершает Renga после выхода — приложение остаётся открытым.

## Инструменты

Все пользовательские координаты, отметки, высоты и толщины — в метрах. `levelId` — локальный числовой ID уровня, который возвращают `renga_list_levels` и `renga_ping`.

### `renga_ping`

Проверка связи с Renga. Возвращает версию и название продукта, наличие проекта, путь к проекту, количество объектов, уровни, оси и признак наличия геометрии.

Параметры: нет.

### `renga_new_project`

Создаёт новый чистый проект. Если проект уже открыт, он закрывается с потерей несохранённых изменений.

Параметры: нет.

### `renga_open_project`

Открывает существующий `.rnp`. Текущий проект закрывается с потерей несохранённых изменений.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `path` | string | да | Путь к `.rnp` |

### `renga_list_levels`

Возвращает уровни проекта: `id`, `uniqueId`, `name`, `elevation` (м), `elevationMm`, `originZ` (м).

Параметры: нет.

### `renga_list_objects`

Возвращает объекты модели: `id`, `uniqueId`, `typeId`, `typeName`, `name`, `levelId` и ID зависимых объектов.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `type` | string | нет | Имя типа (`wall`, `door`, `window`, `level`, ...) или GUID типа |
| `limit` | integer | нет | Максимум объектов. По умолчанию 500 |

### `renga_get_object`

Возвращает подробную информацию об объекте: идентификаторы, уровень, параметры и пользовательские свойства.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `objectId` | integer | да | Локальный ID объекта |
| `includeProperties` | boolean | нет | Включать пользовательские свойства. По умолчанию `true` |

### `renga_list_parameters`

Возвращает все нативные параметры объекта: GUID, имя, текст, группу, тип, `readOnly`, `rawValue`, `value`, единицу и имя связанной сущности для `MaterialId`/`StyleId`.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `objectId` | integer | да | Локальный ID объекта |

### `renga_set_parameter`

Устанавливает нативный параметр по GUID или имени.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `objectId` | integer | да | Локальный ID объекта |
| `parameter` | string | да | GUID или имя параметра |
| `value` | number / string / boolean | да | Новое значение |
| `unit` | string | нет | `m`, `mm`, `cm`, `deg`, `rad`, `m2`, `mm2`, `cm2`, `m3`, `mm3`, `cm3`, `kg`, `g`, `t`, `raw` |

По умолчанию длины и отметки задаются в метрах, углы — в градусах, площадь — в м², объём — в м³, масса — в кг. Для `raw` значение передаётся во внутренних единицах Renga.

Примеры:

```json
{"objectId": 100008, "parameter": "WallThickness", "value": 0.24}
{"objectId": 100008, "parameter": "Mark", "value": "W-01"}
{"objectId": 100016, "parameter": "DoorWidth", "value": 1.1}
```

Некоторые параметры доступны только для чтения. В частности, `ObjectName` у стен, дверей и окон в Renga 9.2 read-only; для маркировки используйте `Mark`.

### `renga_list_materials`

Возвращает простые и слоистые материалы проекта: ID, имя, плотность, цвет, слои.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `kind` | string | нет | `all`, `material` или `layered` |
| `limit` | integer | нет | Максимум элементов. По умолчанию 500 |

### `renga_list_styles`

Без `kind` возвращает список коллекций стилей и их количество. С `kind` — элементы выбранной коллекции.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `kind` | string | нет | `beam`, `column`, `door`, `window`, `plate`, `element`, `pipe`, `duct`, `material`, `layered_material` и другие |
| `limit` | integer | нет | Максимум элементов. По умолчанию 500 |

### `renga_assign_material`

Назначает простой или слоистый материал объекту.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `objectId` | integer | да | Локальный ID объекта |
| `materialId` | integer | да | ID материала или слоистого материала |
| `layered` | boolean | нет | Явно указать тип материала |

Колонны и балки используют `MaterialId`. Стены, перекрытия и крыши используют `LayeredMaterialId`.

### `renga_create_material`

Создаёт простой материал в проекте.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | string | да | Имя материала |
| `density` | number | нет | Плотность, кг/м³ |

### `renga_create_style`

Создаёт нативный стиль.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `kind` | string | да | `door`, `window`, `beam`, `column` или `plate` |
| `name` | string | да | Имя стиля |
| `materialId` | integer | нет | ID материала для стиля |
| `profileId` | integer | нет | ID профиля для балки, колонны или плиты |

Для `beam`, `column` и `plate` нужен существующий профиль. Список профилей: `renga_list_styles` с `kind = "profile"`.

### `renga_list_style_parameters`

Возвращает параметры стиля: GUID, имя, тип, `readOnly`, значение и единицы.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `kind` | string | да | Тип стиля |
| `styleId` | integer | да | ID стиля |

### `renga_set_style_parameter`

Устанавливает параметр стиля. Правила единиц совпадают с `renga_set_parameter`.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `kind` | string | да | Тип стиля |
| `styleId` | integer | да | ID стиля |
| `parameter` | string | да | GUID или имя параметра |
| `value` | number / string / boolean | да | Новое значение |
| `unit` | string | нет | Единица измерения |

### `renga_list_property_definitions`

Возвращает зарегистрированные пользовательские свойства проекта: GUID, имя, тип и значения перечислений.

Параметры: нет.

### `renga_register_property`

Регистрирует новое пользовательское свойство.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | string | да | Имя свойства |
| `type` | string | да | `string`, `double`, `length`, `angle`, `area`, `boolean`, `enumeration`, `integer`, `logical`, `mass`, `volume` |
| `enumeration` | array | нет | Значения для типа `enumeration` |
| `propertyId` | string | нет | GUID свойства. Если не задан, создаётся новый |

### `renga_assign_property`

Назначает пользовательское свойство типу объекта.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `propertyId` | string | да | GUID свойства |
| `objectType` | string | да | Имя типа (`wall`, `door`, ...) или GUID типа |

### `renga_unassign_property`

Снимает пользовательское свойство с типа объекта.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `propertyId` | string | да | GUID свойства |
| `objectType` | string | да | Имя типа или GUID типа |

### `renga_unregister_property`

Удаляет пользовательское свойство из проекта.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `propertyId` | string | да | GUID свойства |

### `renga_set_property`

Устанавливает значение пользовательского свойства на объекте. Свойство должно быть зарегистрировано и назначено типу объекта.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `objectId` | integer | да | ID объекта |
| `propertyId` | string | да | GUID свойства |
| `value` | number / string / boolean | да | Новое значение |

### `renga_create_level`

Создаёт уровень с заданной отметкой.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | string | да | Имя уровня, например `Level 1` |
| `elevation` | number | да | Отметка уровня в метрах |

Особенность: уровни создаются через официальный импорт IFC-заготовки. Вызывайте этот инструмент до создания геометрии.

### `renga_create_axis`

Создаёт координационную ось (нативный `Axis`) между двумя точками в плане.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | string | да | Имя оси, например `A` или `1` |
| `x1` | number | да | X начала, м |
| `y1` | number | да | Y начала, м |
| `x2` | number | да | X конца, м |
| `y2` | number | да | Y конца, м |

Поддерживаются ортогональные и диагональные оси. Вызывайте до создания геометрии.

### `renga_create_wall`

Создаёт прямую стену по базовой линии на уровне.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `x1` | number | да | X начала базовой линии, м |
| `y1` | number | да | Y начала базовой линии, м |
| `x2` | number | да | X конца базовой линии, м |
| `y2` | number | да | Y конца базовой линии, м |
| `levelId` | integer | да | ID уровня-хоста |
| `height` | number | да | Высота стены, м |
| `thickness` | number | нет | Толщина стены, м. По умолчанию берётся из стиля Renga |

Толщину можно задать при создании или позже через `renga_set_parameter` с параметром `WallThickness`.

### `renga_create_column`

Создаёт колонну.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `x` | number | да | X, м |
| `y` | number | да | Y, м |
| `height` | number | да | Высота, м |
| `levelId` | integer | нет | ID уровня-хоста |
| `elevation` | number | нет | Абсолютная отметка основания, м |
| `styleId` | integer | нет | ID стиля колонны из `renga_list_styles` |

Если `levelId` не задан, выбирается ближайший к `elevation` уровень (или самый нижний, если отметка не задана). Если `elevation` не задана, колонна начинается на отметке уровня.

### `renga_create_beam`

Создаёт балку между двумя абсолютными 3D-точками.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `x1` | number | да | X начала, м |
| `y1` | number | да | Y начала, м |
| `z1` | number | да | Z начала, м |
| `x2` | number | да | X конца, м |
| `y2` | number | да | Y конца, м |
| `z2` | number | да | Z конца, м |
| `levelId` | integer | нет | ID уровня-хоста |
| `styleId` | integer | нет | ID стиля балки из `renga_list_styles` |

Если `levelId` не задан, выбирается уровень, ближайший к `z1`.

### `renga_create_door`

Создаёт дверь, привязанную к существующей стене.

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `wallId` | integer | да | ID стены-хоста |
| `x` | number | да | X центра двери на стене, м |
| `y` | number | да | Y центра двери на стене, м |
| `width` | number | да | Ширина двери, м |
| `height` | number | да | Высота двери, м |
| `offset` | number | нет | Вертикальное смещение от уровня, м. По умолчанию 0 |
| `styleId` | integer | нет | ID стиля двери из `renga_list_styles`. По умолчанию 0 — без стиля |

Дверь создаётся как нативный объект `Door`. В пустом шаблоне Renga стили дверей могут отсутствовать, тогда используется стиль «нет» и в IFC дверь экспортируется как проём.

### `renga_create_window`

Создаёт окно, привязанное к существующей стене.

## Управление параметрами и материалами

Типовой сценарий тонкой настройки объекта:

1. `renga_list_objects` — найти объект и получить его `id`.
2. `renga_list_parameters` — посмотреть доступные параметры, их GUID, `readOnly`, текущие значения и единицы.
3. `renga_set_parameter` — изменить нужный параметр.
4. `renga_assign_material` — назначить материал, если объект его поддерживает.

Примеры:

```json
{"objectId": 100008, "parameter": "WallThickness", "value": 0.24}
{"objectId": 100008, "parameter": "Mark", "value": "W-01"}
{"objectId": 100016, "parameter": "DoorWidth", "value": 1.1}
{"objectId": 100003, "parameter": "MaterialId", "value": "Steel"}
```

Особенности:

- Длины и отметки по умолчанию задаются в метрах, углы — в градусах.
- Для `MaterialId` и стилей можно передать имя сущности вместо числового ID.
- `renga_list_parameters` возвращает `referencedName` для связанных материалов и стилей.
- `ObjectName` у стен, дверей и окон в Renga 9.2 доступен только для чтения; для маркировки используйте `Mark`.
- Простые материалы назначаются колоннам и балкам. Стены, перекрытия и крыши используют слоистые материалы; их можно просматривать и назначать, если они есть в проекте.
- В пустом шаблоне Renga коллекции стилей и слоистых материалов могут быть пустыми. Стили можно выбрать при создании, если они есть в проекте.

## Управление стилями и пользовательскими свойствами

Стили:

```json
{"kind": "door", "name": "Моя дверь"}
{"kind": "window", "name": "Моё окно"}
{"kind": "column", "name": "Моя колонна", "profileId": 134270194}
{"kind": "beam", "name": "Моя балка", "profileId": 134270194}
```

Созданный стиль можно сразу передать в `styleId` при создании двери, окна, колонны или балки.

Пользовательские свойства:

```json
{"name": "FireRating", "type": "enumeration", "enumeration": ["R30", "R60", "R90"]}
{"propertyId": "{...}", "objectType": "wall"}
{"objectId": 100008, "propertyId": "{...}", "value": "R60"}
```

Порядок: `renga_register_property` → `renga_assign_property` → `renga_set_property`.

Особенности:

- В новом проекте Renga (`renga_new_project`) уже есть стандартные стили, профили и материалы.
- После `renga_create_level` / `renga_create_axis` проект пересобирается через IFC-импорт, и стандартные стили, профили и материалы могут отсутствовать. Поэтому стили дверей/окон можно создать заново, а для балок/колонн/плит нужен профиль.
- Создание слоистых материалов через публичный API не реализовано: у `ILayeredMaterial` нет сеттеров слоёв. Существующие слоистые материалы можно смотреть и назначать.
- `renga_create_style` поддерживает `door`, `window`, `beam`, `column`, `plate`. Стили MEP и `ElementStyle` требуют дополнительных данных и пока не создаются.

## Рекомендуемый порядок работы

1. `renga_new_project`
2. `renga_create_level` для всех этажей, например 0, 3, 6 м
3. `renga_create_axis` для всех осей, например A, B, 1, 2
4. `renga_list_levels` — получить `levelId`
5. `renga_create_wall`, `renga_create_column`, `renga_create_beam`, `renga_create_floor`
6. `renga_create_roof`
7. `renga_create_door` и `renga_create_window` — в уже созданные стены
8. `renga_create_opening` — в перекрытия и крыши
9. `renga_create_wall_foundation`, `renga_create_isolated_foundation`, `renga_create_plate`
10. `renga_create_room` — после стен, чтобы Renga рассчитала контур
11. `renga_create_stair`, `renga_create_railing`, `renga_create_ramp`
12. `renga_create_drawing` — листы чертежей; стиль оформления можно получить через `renga_list_drawing_resources`
13. `renga_save_project`
14. `renga_export_ifc`
15. `renga_export_drawing` или `renga_export_all_drawings` — PDF, DXF, DWG или XPS

Порядок «уровни и оси → геометрия» важен: после появления геометрии добавить уровень или ось через публичный COM API Renga нельзя.

## Особенность работы с уровнями и осями

Публичный COM API Renga 9.2 имеет ограничения:

- `ILevel.Elevation` доступно только для чтения.
- Параметр `LevelElevation` доступен только для чтения.
- `IModel.CreateObject` для `Level` игнорирует `Z` в `Placement3D`, и уровень создаётся с отметкой 0.
- `IModel.CreateObject` для `Axis` возвращает `null`.

Поэтому сервер использует официальный маршрут: генерирует временный IFC4-файл с уровнями и/или осями, импортирует его через `IApplication.ImportIfcProject`, проверяет результат и удаляет временные объекты-носители. В проекте остаются настоящие объекты Renga типов `Level` и `Axis`.

Что это значит на практике:

- `renga_create_level` и `renga_create_axis` пересобирают каркас уровней и осей.
- Их нужно вызывать до создания стен, колонн, балок и перекрытий.
- Если геометрия уже есть, инструменты возвращают понятную ошибку и не меняют проект.
- Временный IFC создаётся в `%TEMP%\RengaMcp` и удаляется после импорта.
- Импортированные уровни и оси сохраняются в `.rnp` и переживают закрытие и повторное открытие.

Если открыть готовый проект с осями после перезапуска MCP-сервера, сервер увидит оси, но не сможет прочитать их координаты через COM: у `Axis` нет публичного getter геометрии. В этом случае добавление новых уровней и осей блокируется, а создание геометрии продолжает работать.

## Проверка MCP вручную

Сервер читает по одной JSON-RPC строке из stdin и пишет по одной строке в stdout. Минимальная последовательность:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"manual-test","version":"1.0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"renga_ping","arguments":{}}}
```

Логи сервера должны идти в `stderr`, а не в `stdout`.

## Перегенерация COM interop

Interop-сборка уже включена в репозиторий: `libs/Interop.RengaCOMAPI.dll`. Она сгенерирована из типа библиотеки установленной Renga:

- TypeLib GUID: `{0EC5D324-8B9F-4D30-84ED-AB711618D1C1}`
- Файл типа библиотеки: `C:\Program Files\Renga Professional\RengaCOMAPI.dll`

Если вы обновили Renga или используете другую версию, interop нужно перегенерировать.

`TlbImp.exe` входит в Windows SDK, например:

```text
C:\Program Files (x86)\Microsoft SDKs\Windows\v10.0A\bin\NETFX 4.8 Tools\x64\TlbImp.exe
```

`TlbImp.exe` может не найти `TLBREF.DLL`. Надёжный способ — скопировать оба файла в один временный каталог и запускать оттуда:

```powershell
$work = "C:\Temp\renga-tlbimp"
New-Item -ItemType Directory -Force -Path $work | Out-Null

Copy-Item "C:\Program Files (x86)\Microsoft SDKs\Windows\v10.0A\bin\NETFX 4.8 Tools\x64\TlbImp.exe" "$work\TlbImp.exe" -Force
Copy-Item "C:\Windows\Microsoft.NET\Framework64\v4.0.30319\TLBREF.DLL" "$work\TLBREF.DLL" -Force

& "$work\TlbImp.exe" `
  "C:\Program Files\Renga Professional\RengaCOMAPI.dll" `
  /out:"C:\Tools\RengaMcpServer\libs\Interop.RengaCOMAPI.dll" `
  /namespace:Renga `
  /machine:X64
```

После замены DLL пересоберите проект:

```powershell
& "C:\Program Files\dotnet\dotnet.exe" build -c Release
```

Для 32-битной Renga генерируйте interop x86 и измените `PlatformTarget` в `.csproj` на `x86`.

## Ограничения и безопасность

- Сервер предназначен для локального использования и не имеет аутентификации.
- `renga_new_project` и `renga_open_project` закрывают текущий проект с потерей несохранённых изменений.
- `renga_save_project` перезаписывает существующий `.rnp`.
- Пересборка уровней и осей выполняется только при отсутствии геометрии.
- Координаты осей нельзя прочитать обратно через COM; после перезапуска сервера добавление осей и уровней в проект с осями блокируется.
- `ObjectName` у стен, дверей и окон в Renga 9.2 доступен только для чтения. Для маркировки используйте параметр `Mark`.
- `renga_create_opening` создаёт проём только в перекрытии или крыше. Для проёмов в стенах используйте двери и окна, в том числе без стиля (`styleId = 0`).
- `renga_create_plate` создаёт нативную пластину Renga (профильный элемент), а не плиту перекрытия. Для плит и перекрытий используйте `renga_create_floor`.
- `renga_create_room` вычисляет контур по существующим стенам. Если вокруг точки нет замкнутого контура, область помещения может быть пустой.
- `renga_create_railing` сохраняет только прямую базовую линию: Renga не сохраняет ломаную для ограждения, поэтому сложные ограждения собираются из нескольких сегментов.
- У лестницы, пандуса, фундаментов и ограждений часть параметров вычисляется Renga и доступна только для чтения (`RiserHeight`, `TreadDepth`, `StairSlope`, `RampSlope`, `RampThickness`, `RailingOffset` и другие).
- `renga_create_drawing` создаёт лист, но публичный API Renga 9.2 не позволяет создавать содержимое листа: `DrawingLine`, `DrawingText`, `DrawingImage`, `EmbeddedModelView`, `EmbeddedTable`, `EmbeddedSchedule` и `EmbeddedLegend` не создаются через `IModel.CreateObject` даже при открытом виде чертежа.
- `LinearDimension`, `Tag`, `Elevation`, `Section` и другие аннотации модели возвращают ошибку «Creation of an object of this type is not supported». Публичного API для их создания нет.
- `drawingId` — стабильный GUID листа; `index` в ответах `renga_list_drawings` служит только для отображения. После создания или удаления листов индексы могут меняться, поэтому в операциях используйте `drawingId`.
- Штампы листа доступны только для чтения: `ITitleBlockInstance` позволяет прочитать строки и столбцы, но не изменить их.
- Определения таблиц и спецификаций можно создать как сущности проекта, но публичного API для редактирования их содержимого нет, поэтому сервер эти инструменты не предоставляет.
- Простые материалы назначаются колоннам и балкам. Стены, перекрытия и крыши используют слоистые материалы; создание слоистых материалов в текущей версии не реализовано, но существующие можно просматривать и назначать.
- Новый проект Renga содержит стандартные стили, профили и материалы. После пересборки через IFC-импорт (`renga_create_level` / `renga_create_axis`) они могут отсутствовать; стили можно создать заново, но для балок, колонн и плит нужен существующий профиль. Создание профилей пока не реализовано.
- При нескольких запущенных экземплярах Renga ROT может вернуть не тот экземпляр. Для предсказуемой работы держите один экземпляр.
- Interop-сборка сгенерирована из установленной Renga. При публикации проекта проверьте условия лицензирования Renga и её SDK.
- Лицензия самого проекта пока не выбрана.

## Диагностика

### `dotnet` не найден

Используйте полный путь:

```powershell
& "C:\Program Files\dotnet\dotnet.exe" build -c Release
```

Либо добавьте `C:\Program Files\dotnet` в `PATH`.

### `Renga.Application.1 is not registered`

- Запустите Renga вручную и убедитесь, что она работает.
- Проверьте разрядность: interop и сервер должны быть x64 для 64-битной Renga.
- При необходимости переустановите или восстановите Renga.

### Первый вызов долго не отвечает

Если Renga не была запущена, сервер запускает её. Первый вызов может занять 10–30 секунд.

### `Cannot create a level after geometry exists`

Это ожидаемое ограничение. Создайте новый проект и сначала все уровни и оси, затем геометрию.

### `IFC seed verification failed`

Импорт IFC не создал ожидаемые уровни или оси. Проверьте версию Renga и лог в `stderr`. Для другой версии Renga может потребоваться перегенерация interop или обновление генератора IFC.

### `Renga already has an active operation`

Предыдущая операция не завершилась. Перезапустите Renga и повторите вызов.

### MCP-клиент не видит инструменты

- Проверьте абсолютный путь к `.exe` в конфигурации.
- Перезапустите клиент.
- Проверьте логи MCP-клиента: сервер пишет диагностику в `stderr`.
- Убедитесь, что `stdout` не засоряется посторонними сообщениями.

## Ограничения API Renga

Ниже перечислены ограничения публичного COM API Renga, с которыми столкнулись при разработке. Часть из них обходится через официальный IFC-импорт, часть остаётся неустранимой на уровне API.

- **Отметка уровня.** `ILevel.Elevation` доступна только для чтения. Параметр `LevelElevation` тоже read-only. `IModel.CreateObject` для `Level` игнорирует `Z` в `Placement3D`, поэтому уровень создаётся с отметкой 0.
- **Создание осей.** `IModel.CreateObject` для `Axis` возвращает `null`. Публичного конструктора осей нет; оси создаются через импорт IFC-заготовки.
- **Геометрия осей.** У `Axis` нет публичного getter базовой линии. Координаты осей нельзя прочитать через COM, поэтому после перезапуска сервера добавление уровней/осей в проект с осями блокируется.
- **Пересборка уровней и осей.** `IApplication.ImportIfcProject` создаёт новый проект и не умеет добавлять данные в текущий. Поэтому пересборка уровней/осей заменяет проект и может лишить его стандартных стилей, профилей и материалов.
- **Имена объектов.** `ObjectName` у стен, дверей и окон в Renga 9.2 read-only. Параметр `Mark` доступен для записи. `LevelName` и `GridLineName` доступны для записи.
- **Слоистые материалы.** `ILayeredMaterial` не предоставляет сеттеров слоёв, поэтому создать управляемый слоистый материал через публичный API нельзя. Существующие слоистые материалы можно читать и назначать объектам.
- **Материалы стен, перекрытий и крыш.** Эти объекты используют `LayeredMaterialId`, а не `MaterialId`. Простые материалы назначаются колоннам и балкам.
- **Профили.** Публичного создания профилей нет. Для стилей балок, колонн и плит нужен существующий `ProfileId`.
- **Создание стилей.** `IEntityCollection.Create` для стилей возвращает `null` вне активной операции. Создание работает внутри `IOperation`. Поддерживаются стили `door`, `window`, `beam`, `column`, `plate`; стили MEP и `ElementStyle` требуют дополнительных данных.
- **Двери и окна без стиля.** При `StyleId = 0` или отсутствии стилей в проекте двери и окна экспортируются в IFC как `IfcOpeningElement`, а не как `IfcDoor` / `IfcWindow`.
- **Хосты проёмов.** `Opening` нельзя разместить на стене: Renga возвращает `null` с сообщением, что объект этого типа не может быть расположен на данном хосте. Проёмы создаются в перекрытиях и крышах; для стен используются `Door` и `Window`.
- **Параметры хоста при создании проёма.** Плоскость проёма задаётся `Placement3D`, поэтому сервер ставит его на абсолютную отметку хоста (уровень плюс `ElevationAboveLevel`). Иначе при совпадающих отметках перекрытия и крыши проём может попасть не в тот объект.
- **Пластина.** `Plate` — это профильная пластина (`Пластина`), а не плита перекрытия. У неё нет `IBaseline2DObject`; геометрия определяется стилем-профилем, толщиной и точкой вставки.
- **Помещения.** `Room` создаётся в контрольной точке, а контур вычисляется по окружающим стенам через `IRoom.CalculateRegion`. Без замкнутого контура область может быть пустой.
- **Ограждения.** Для `Railing` Renga сохраняет только прямую базовую линию: ломаная, переданная через `IBaseline2DObject`, не сохраняется.
- **Целочисленные параметры новых объектов.** У лестницы, фундаментов и пандуса параметры-перечисления и целочисленные параметры (форма, положение, количество ступеней) не применяются в операции создания: сеттер возвращает `RPC_E_SERVERFAULT`. Сервер сначала применяет геометрию и double-параметры, а затем отдельной операцией устанавливает целочисленные параметры.
- **Вычисляемые параметры.** У лестницы, пандуса и ограждения часть размеров вычисляется Renga и доступна только для чтения: `RiserHeight`, `TreadDepth`, `StairSlope`, `RampSlope`, `RampThickness`, `RailingOffset`.
- **Содержимое листов чертежа.** Листы создаются, переименовываются, удаляются и экспортируются, но публичный API Renga 9.2 не даёт создать их содержимое. `DrawingLine`, `DrawingText`, `DrawingImage`, `EmbeddedModelView`, `EmbeddedTable`, `EmbeddedSchedule` и `EmbeddedLegend` возвращают ошибку «It is impossible to create an object of this type in 3D view or Assembly» даже при активном виде чертежа. `LinearDimension`, `Tag`, `Elevation` и `Section` возвращают «Creation of an object of this type is not supported».
- **Доступ к IDrawing.** В Renga 9.2 `Drawings2.GetByIndex(i) as IDrawing` и `GetInterfaceByName("IDrawing")` не работают (E_NOINTERFACE), хотя пример в документации использует именно этот способ. Сервер получает `IDrawing` через устаревшую коллекцию `IProject.Drawings` и сопоставляет листы по GUID.
- **Пакетный экспорт PDF.** `IProject.ExportDrawingsToPdf` в проверенной версии падает с `Typelib export: Type library is not registered`, поэтому `renga_export_all_drawings` экспортирует листы по одному через `IDrawing.ExportToPdf`.
- **Штампы и таблицы.** `ITitleBlockInstance` доступен только для чтения. Определения таблиц и спецификаций создаются как сущности проекта, но API для редактирования их содержимого отсутствует.
- **Параметры.** Не все параметры доступны для записи. Часть из них read-only. Значения double-параметров хранятся во внутренних единицах Renga; сервер конвертирует метры, градусы, м², м³ и кг, но для нестандартных параметров можно использовать `unit: "raw"`.
- **Количества.** У `IQuantityContainer` нет перечисления GUID, поэтому нельзя универсально перечислить все количества объекта. Для чтения количеств нужен явный список известных GUID.
- **Размеры и теги.** `LinearDimension`, `Tag`, `DrawingAxis` и подобные аннотации не создаются через публичный `IModel.CreateObject` и не имеют публичного API привязки к геометрии.
- **Перемещение и поворот.** `ILevelObject.SetPlacement` не поддерживается для `Door`, `Window`, `Opening`, `Room`, `Level` и объектов с зависимыми объектами. Для них требуется пересоздание или специализированные параметры.
- **IFC.** Поддерживается экспорт IFC и импорт IFC как нового проекта. Добавление IFC в текущий проект и гарантированный перенос стилей/профилей из IFC не поддерживаются.
- **Несколько экземпляров Renga.** При нескольких запущенных процессах ROT может вернуть не тот экземпляр. Для предсказуемой работы нужен один экземпляр Renga.
- **Версии Renga.** Interop-сборка сгенерирована из установленной версии Renga и не гарантирует совместимость с другими версиями без перегенерации.
